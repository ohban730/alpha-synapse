# 2. プログラムの解説と仕組みの探究

この章では、本アプリを再構築するために、各ソースコード（ファイル）がどのような仕組みで動いているのかを解説します。

プログラミング初心者の方でも理解しやすいように、ソースコードの要所要所を噛み砕き、重要なアルゴリズムの仕組みを図解します。

---

## 🔰 【入門】JavaScriptの基本概念の例え話

解説の中で出てくるプログラミング用語を、3Dアバターに例えて説明します。

- **クラス (Class)**:
  - **例え**: **「アバターの設計図」**です。「アバターはこんな関節を持っていて、瞬きや呼吸ができる」という定義をまとめたものです。
- **インスタンス (Instance)**:
  - **例え**: **「実際に3D空間に出現したアバターそのもの」**です。設計図（クラス）から実体化した実物です。
- **プロパティ (Property) / 変数**:
  - **例え**: **「アバターの状態（パラメータ）」**です。今しゃべっているか（`isSpeaking = true`）、今の身長はいくらか、などの情報（データ）を保持します。
- **メソッド (Method) / 関数**:
  - **例え**: **「アバターの動作（命令）」**です。口を「あ」の形にする（`setViseme('aa')`）、まばたきをする、といった具体的な処理の実行手順です。

## 1. 🕴️ `src/vrm-avatar.js` (アバター制御)
アバターのロードや、呼吸・視線追従などの「生きているような動き」を制御するクラス `VRMAvatar` を定義しています。

### 🌟 コアアルゴリズム①：関節のねじれ防止 (相対回転)
3Dアバターの関節を曲げる際、単純に「腕を90度曲げる」という命令を送ると、アバターのモデルが元々持っている初期姿勢（Tポーズなど）の角度が無視され、腕が不自然にねじれてちぎれたようになってしまうバグ（ジンバルロックやねじれバグ）が起きます。

これを防ぐため、本アプリでは**「初期回転状態に、曲げたい角度を掛け合わせる」**という計算を行っています。

- **実装の仕組み**:
  1. モデルを読み込んだ瞬間、各関節（肩、肘、手など）の最初の角度（向き情報）を `defaultRotations` という変数に保存（クローン）しておきます。
  2. ポーズを変更するときは、この `defaultRotations` をベースにして、そこからどれだけ動かすか（相対的な角度）を計算します。
  3. 3D空間の回転計算には **クォータニオン (Quaternion)** という特殊な計算方法を用います。クォータニオンの掛け算（`.multiply`）を行うことで、「初期姿勢から見て、腕を内側に30度、前に15度曲げる」といった、ねじれのない滑らかなポーズ変更（`interpolateJoint`）を実現しています。

```
【ねじれ防止のイメージ】

 ❌ 悪い例: アバターの関節角度を [曲げたい角度] に直接上書きする
            (初期姿勢のデータが破壊され、腕がちぎれたような向きになる)

 ⭕ 良い例: [初期姿勢の角度] ✖ [曲げたい角度] ＝ [最終的な角度] 
            (初期姿勢をベースに相対的に動かすため、滑らかに曲がる)
```

### 🌟 コアアルゴリズム②：リップシンク (プロシージャル口パク)
AIの音声データから口の形を完全に解析するのは難しいため、本アプリでは**「しゃべっている文字」から母音を推測して口を動かす**という簡易日本語解析（`startLipSyncLoop`）を行っています。

- **仕組み**:
  1. AIのセリフテキストを1文字ずつスキャンします。
  2. 文字が「あ・か・さ・た・な…」なら母音は「あ（aa）」、「い・き・し…」なら「い（ih）」と判定します。
  3. 判定した母音に対応する表情データ（ブレンドシェイプ）の数値（0.0〜1.0）を LERP（直線補間）という手法で滑らかに変化させ、アバターの口を「あ・い・う・え・お」の形に変形させます。

## 2. 🧠 `src/ai-brain.js` (AIの思考と感情連携)
AIとの会話の受け渡しや、会話履歴（コンテキスト）の管理を行うクラス `AIBrain` です。

### 🌟 コアアルゴリズム：感情タグの抽出
システムプロンプト（AIへの命令書）で、AIに対して「発言の最後に必ず `[happy]` や `[sad]` などの感情タグを付けて出力してください」と指示しています。

プログラムはAIから返ってきた文章を**正規表現**という文字列探索機能を使ってパース（解析）します。

```
【感情タグの抽出フロー】

 [AIの返答]: 「マスター、今日もよろしくね。[happy]」
                │
                ▼ (正規表現で探索)
 ┌──────────────┴──────────────┐
 ▼                             ▼
[セリフテキスト]              [感情タグ]
「マスター、今日もよろしくね。」   "happy"
    │                          │
    ▼ (字幕表示へ)              ▼ (アバターへ適用)
  「マ・ス・タ・ー...」        表情を笑顔にし、喜ぶポーズに変更
```

## 3. 🎙️ `src/voice-system.js` (音声認識・合成と波形演出)
マイクから声を拾い（STT）、AIのセリフを喋らせ（TTS）、声に合わせて波形を動かすクラス `VoiceSystem` です。

### 🌟 コアアルゴリズム：WAVヘッダーの自動注入
Gemini API の音声合成（Native TTS）機能は、時折ヘッダー（データの身元情報）がない「生データ（PCM形式のバイナリ）」を返します。ブラウザの音楽プレイヤーは、ヘッダーがないと「何のファイルか（サンプリングレートやチャンネル数など）」がわからず、再生できません。

これを解決するため、プログラム側で**「44バイトのWAVヘッダー」**を自前で作成し、生データの先頭にガッチャンコ（結合）して再生可能な音声ファイル（Blob）に変換しています（`pcmToWavBlob`）。

```
【WAVヘッダーの結合イメージ】

 ┌──────────────────────────────────────────────────────────┐
 │ WAVヘッダー (44バイト)                                    │
 │ - "RIFF" / "WAVE" という目印                              │
 │ - サンプリング周波数 (24000Hz)                             │
 │ - モノラル(1ch) / 16ビットPCM                              │
 └────────────────────────────┬─────────────────────────────┘
                              │ (結合して Blob 化)
                              ▼
 ┌──────────────────────────────────────────────────────────┐
 │ 生PCM音声データ (Geminiから届いたバイナリ)                │
 └──────────────────────────────────────────────────────────┘
```

## 4. 🎛️ `src/floating-hud.js` (SF風3Dディスプレイ)
アバターの左右に浮かぶ、近未来的なHUD（HolographicPanel, TacticalRadar）を作るクラスです。

### 🌟 コアアルゴリズム：CanvasTexture 転写
ブラウザの中に浮かぶ 3D の半透明な板に、文字やサイバー風のデザインを描くために、**「見えない2Dの画用紙（Canvas）にお絵描きして、それを3Dの板にシールのように貼り付ける」**という手法（`CanvasTexture`）を使っています。

- **仕組み**:
  1. メモリ上に非表示の `<canvas>` 要素を作成します。
  2. JavaScript の 2D 描画機能（`CanvasRenderingContext2D`）を使って、ネオンカラーの枠線やテキスト、点滅するドットを描き込みます。
  3. Three.js の `CanvasTexture` という機能を使って、このキャンバスを3D空間の板（平面メッシュ）の「模様（テクスチャ）」として登録します。
  4. 文字が変わるたびにキャンバスを塗り直し、テクスチャの更新フラグ（`needsUpdate = true`）を立てることで、リアルタイムに文字が書き換わる3Dディスプレイを実現しています。

## 5. 🎬 `src/main.js` (全体指揮者とXR連携)
3D空間の作成、ライトの配置、WebXRのセッション管理、および各モジュールの連携を行うメインプログラムです。

### 🌟 コアアルゴリズム：3Dレーザーポインターによるクリック判定 (Raycasting)
VR/ARモード時、ユーザーはVRコントローラーから青いレーザー光線を発射して、空間に浮かぶ 3D画面（HolographicPanel）をクリックします。
3D空間にある板の「どこ」を撃ち抜いたかを判定し、さらに「ボタンが押された」ことを検出するために、**レイキャスティング**と**UVマッピング**という技術を組み合わせています。

```
【レイキャストとUV・ピクセル変換】

  🥽 [VRコントローラー] ─────── 指向レーザー ───────> 🎯 [3D板 (HolographicPanel)]
                                                        │ (交差点を検出)
                                                        ▼
                                                  [UV座標 (0.0 ～ 1.0)]
                                                  例: X=0.8, Y=0.2
                                                        │ (キャンバスサイズ 512x384 を掛ける)
                                                        ▼
                                                  [キャンバス内のピクセル位置]
                                                  例: X=409px, Y=76px
                                                        │
                                                        ▼
                                                  「原本を開くボタン」の範囲内か判定！
```

- **仕組み**:
  1. コントローラーの向きからビーム（Ray）を飛ばし、3D画面の板と交差するか計算します（`raycaster.intersectObject`）。
  2. 交差した場合、板の上の交点位置が **UV座標**（左下を `(0,0)`、右上を `(1,1)` とする割合の座標）として取得できます。
  3. このUV座標に、お絵描きキャンバスのサイズ（横512px、縦384px）を掛け算することで、キャンバス上の「何ピクセル目をクリックしたか」を正確に割り出します。
  4. そのピクセル座標が「BACK TO FEED」ボタンや「ニュース項目」の描画範囲内であれば、クリックイベントを実行します。

## 6. 📰 `public/news-portal.html` (ニュース・検索ポータル)
Web Visor（前面のブラウザ画面）の中に表示されるHTMLファイルです。

### 🌟 コアアルゴリズム：親画面との双方向通信
このファイルは `<iframe>`（インラインフレーム）という、メイン画面とは隔離された小窓の中で動いています。しかし、ニュースをクリックした時にアバターを「考えるポーズ」にさせたり、音声読み上げをトリガーしたりするには、小窓からメイン画面へ命令を送る必要があります。

本アプリでは、同一ドメイン（同じアドレス空間）で動いている利点を活かし、**`window.parent`** という仕組みを使って小窓から親の JavaScript 関数を直接呼び出しています。

- **小窓から親への命令例**:
  `window.parent.speakNews(speakText, activeInsight);` （親画面の音声合成を起動）
- **親から小窓への命令例**:
  `visorIframe.src = '/news-portal.html?q=...';` （URLパラメータを使って小窓に検索ワードを渡す）
